# FB1 sim side: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four sim packages of feedback plan 1 (close early + sold-out walk-ups, relaxed
night + night brief, station slots, hurried bots + night planner) on `fb1` as tested selectors and
inputs the UI lane builds on.

**Architecture:** Pure deterministic sim over one `GameState`; every new behaviour is a night or
day input validated in `validate.ts`, applied in the owning module, surfaced to the UI through a
pure selector whose shape sits at the top of its file. Four tracks run on their own branches cut
from `fb1` and merge in a fixed order so version numbers never race.

**Tech Stack:** TypeScript 5.9, Vitest (tests beside sources), tsx for `scripts/`.

**Spec:** `docs/superpowers/specs/2026-10-29-fb1-sim-design.md` (binding), which argues from
`docs/FEEDBACK_PLAN_1.md` §3–4. Code maps for implementers:
`<scratchpad>/fb1/map-day-night.md` and `<scratchpad>/fb1/map-stations-bots.md`.

## Global Constraints

- RNG only through `rngNext`/`rngInt` on `state.rng`; no `Math.random`, `Date`, or unordered
  iteration in `src/sim`. Café runs that do not use a new feature keep an identical RNG stream
  and identical `JSON.stringify(state)` after 900 day ticks; each track adds that test.
- Versions are assigned: sim-day SNAPSHOT 23 / PROTOCOL 26; sim-night 24 / 27; sim-slots 25 / 28;
  sim-bots no bump unless a shape changes. Each bump has a `MIGRATIONS[from]` step and a test
  that calls `migrateSnapshot(from, old)`. Update the pins in `stores.test.ts` and
  `protocol.test.ts`.
- New inputs: a `validateInput` case (shape only), applied only in the right phase, only for a
  connected human (`!p.bot && p.connected`), with a refusal test for each condition.
- Never edit `src/ui`, `src/render`, `src/audio`, `src/main.ts`, `index.html`, `public/`. The one
  allowed exception is a one-line re-export in `src/ui/viewModels.ts` for `profitOf` (Track B),
  listed in the report.
- Green before every merge: `npx vitest run`, `npx tsc --noEmit -p .`, `npm run build`, then
  `npx tsx scripts/balance.ts --weeks 40 --policy smart --summary` and `--policy taste`
  (and `--policy planner` once it exists). Numbers go in `docs/BACKLOG.md` under
  `## FB1 WPn reflection`; player lines under `## Unreleased` in `CHANGELOG.md`.
- Commits: conventional prefixes, trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
  Implementers commit on their branch only; the controller merges and pushes.
- Baseline (main e276359): 86 files / 596 tests; smart mean cash 260.53 score 276.53 loss 26.4%
  profit 97.5%; taste 274.88 / 288.19 / 28.1% / 100%.

## Review Focus

1. A player who votes to close and then disconnects: the remaining voters must still close the
   shop that tick (per-tick check, not per-input). Test in Task A1.
2. Relaxed night with every human gone (all `connected: false`): the night must still open
   (last call starts at once). Test in Task B1.
3. A sold-out board with the menu entirely switched off must spawn nobody and count no walkouts
   (nothing on the board is not "sold out"). Test in Task A2.
4. Removing the only grinder while a bot holds grounds: the bot must not loop; it drops the
   grounds on the floor (no bin) or bins them (bin present). Test in Task C3.
5. A `slot` input that places a kind not in `equipment`, or indexes past the tier's slot count,
   must be ignored without touching `state.stations`. Test in Task C2.
