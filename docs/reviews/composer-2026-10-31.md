## 2. Full critique by area

### Performance

**What’s healthy.** Host-authoritative 60 Hz pure sim in a Worker; 20 Hz snapshots with delta patches (`snap` / `snapd`); measured full snaps ~11 KB, deltas ~0.8 KB. Sim RNG is seeded; no `Math.random` / `Date.now` in `src/sim`. Bot pathfinder ties break by insertion order.

**Hot costs.**
- `step()` → `structuredClone(state)` every tick (`src/sim/step.ts`): largest systemic alloc.
- Worker `postMessage` clones again; keyframes clone for peers.
- HUD `render` ~20 Hz with keyed HTML; patience bars still patch often. Night can rewrite `innerHTML` on structure key change.
- Pixi: Graphics clear/redraw on counts, pickup, actors when keys change — acceptable if keys stay stable; station rebuild on layout key is rare but heavy.

**Catch-up.** `MAX_CATCHUP_TICKS = 10` can drop ticks under load. Host stays authoritative; “ideal” wall-clock timeline diverges. Fine for friends; document for telemetry analysis.

**Recommendation.** Profile one Gear café day with 4 players before Phase 6 polish. Prefer incremental mutability or a pool of scratch states for `step`, and keep DOM keys tight. Do not micro-optimise cosmetics first.

### UI / UX / menus

**Strengths.** Title is charming; character creator is skippable; night tabs with step numbers; crew tips with “Do it”; Restock mid-day (3.7.1) is the right answer to “I forgot beans”; grow-on-receipt matches Kennedy’s night-clutter ruling; `?dev=1` DEV badge + pause is honest.

**Friction (played local `?dev=1` and live title).**
- First night opens Restock with nothing to sell yet → cognitive whiplash.
- Night timer runs until you open DEV → Pause; reviewers expected auto-pause. Design is button-based (not a bug), but discoverability is weak.
- Day HUD: SOLD OUT dominates; morning note is too long during play; bottom key legend lists too many bindings at once.
- “Do bot!” role tag on bots reads like leftover debug chrome.
- “Nothing here!” on mis-aimed E is too vague.
- Office-run phone card / feed / waiting browsers / ring-up bar / jug+steam meters still absent (HANDOFF list).

**Co-op.** Host-authoritative model is clear in README. Lobby copy-code only; join links still deferred (BACKLOG). No input rate limit / player cap — accepted among friends.

**1280×800 / 1512×982.** Night board and day side panels need a pass at 1280×800; right column density will clip. Hire cards (branch `05`) wrap; worth a Playwright check before merge.

### Visual design and game feel

**Keep.** Warm peach night board, Fredoka/Nunito, stand/cart outdoor looks (3.4.0), fridge art, sink, Pixi diorama that already “looks like a real game.”

**Gaps.** Tray table / syrup rack had no art (now basic sprites on `03`). Wand art on espresso, jug/steam meters, waiting-area silhouettes, feed phone UI, rearrange ghosts — still open. Juice (dings, shake) from Phase 2 is present; new systems need matching bubbles (`tray.*`, `line.complain`, `review.post`, `order.addon`).

**Feel.** Movement is responsive. Opening with zero stock + sold-out board is emotionally wrong for a grand opening. A soft gate (“stock at least one pack or buy a fridge”) or a guaranteed starter pack on night 0 would land better without rewriting Gear’s scratch-start fantasy.

### Gameplay and economy

**What works.** Gear trees with silly names and real trade-offs; cold cups + sink + fridge + closing soon make the café feel physical; bots as helpers (not gods) match “co-op first”; Strategist as paid honesty (Round 3) is a clean design; rush restock (+25%) is a good mid-day panic valve.

**Grind / simplicity / bloat.**
- Night still asks a lot even after declutter: gear trees + stock + specialists + rival + branch. Hire cards add two more decisions — intentional, but watch first-night cognitive load.
- Hand-made lattes (fill jug, steam meter, syrup) + trays + rearrange in one week is a lot of skill surface for friends’ game night. If UI ships all three at once, teach one per night or soft-gate.
- Economy: Kennedy’s ruling is playtest-driven, not bot sweeps — respect that. Stand price squeeze was intentional; don’t “fix” difficulty by silent buffs.

**Disagree (argue, don’t reverse):** “No save backwards compatibility for now” is right for velocity, wrong for a public Pages build once non-dev friends return weekly. Before 1.0, either resume migrations or a loud “your save is from an old build — start fresh” with one-click wipe. Decision already says recheck before 1.0 — keep that date honest.

### Code health

**Strengths.** Lane split (sim vs UI) via HANDOFF is unusually clear; pure sim + Vitest density (~1800 tests) is the project’s real asset; protocol/snapshot comments are a living changelog; Gear flag cleanup and classic shop deletion (3.7.0) reduced dead paths.

**Risks.**
- UI/render tests thin vs sim; layers/`scene`/`hud` regressions are easy.
- `src/data/equipment.ts` still exists for UI leftovers in places; finish deleting with the sim kinds when UI is clean.
- ROADMAP / morning prompt docs lag releases by versions.
- `delta.ts` throws on bad patches — can surface as peer frame errors.

**Determinism.** Core is clean. Cosmetic RNG in fx/chaos/audio is fine. Object key iteration on supplies/menu assumes stable insertion — keep builders disciplined.

5. **Hire cards** (`05`) + receipt `hireWages` line.
6. **Perf spike:** replace per-tick `structuredClone` with copy-on-write or dual-buffer state (plan only; NEEDS APPROVAL).

### Sound good, won’t work (or not yet)

- **Full AI teammates next (Phase 5 early).** Budget, determinism, and “scripted bots still make the drinks” exist for a reason. Shipping B7/B8 UI first is higher EV.
- **Player-to-player collision spills at 60%.** Fun fantasy; needs stable collisions and will punish co-op more than bots. Kennedy’s guess is a playtest dial, not a merge-day constant.
- **Split money pools in co-op.** Breaks the shared-café fantasy and night economy readability; keep Later.
- **Rewriting the HUD in React/Pixi-only.** DOM overlays are working; a rewrite burns a week for polish Phase 6 can do incrementally.
- **Silent economy buffs from bot sweeps.** Violates Kennedy’s ruling; bots are minor.
- **2v2 versus (B7) before travel + spike answers.** Spike doc says don’t start V1 until open questions land.

### Disagree with a Decision (not reversed)

**“No save backwards compatibility for now.”** Correct for two agents slamming `main`. Wrong for returning playtesters on Pages. Proposal: keep refuse-old-saves, but add a title-screen explanation and one-button clear — still no migrations until 1.0.
